Troubleshooting

Common issues while configuring, running or changing subject_tracking_master_plot, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

The run fails with “No data returned from EarthRanger for get_subjects”

No subjects matched. Pick the Subject Group Name from the drop-down rather than typing it, so it matches the group in EarthRanger exactly. Leave it empty to check all subjects, and turn Include Inactive on if the group only has inactive subjects. The account also needs permission to see the group.

The dashboard

The run finishes but the dashboard has no diagram

Steps are skipped when one of their inputs is empty. If the site has no subject–source assignments, or no sources this account can see, the diagram step is skipped and nothing is drawn. Check in EarthRanger that the subjects have devices assigned.

“Sources with no subject” lists far more devices than expected

Sources are fetched for the whole site, and unassigned ones are always drawn. When you filter by a subject group, devices on subjects outside that group show up here too. That is expected; check them against the other groups before acting on them.

A source pill has a red outline and a short ID for a name

An assignment points at a source that isn't in the sources list: it was deleted, or this account can't see it. Click the pill for its details card and copy the full ID, then fix or remove the assignment in EarthRanger.

A line and its date are red, marked ⚠

The assignment's start or end date couldn't be read. The label shows the first 10 characters of the bad value. Correct the date on the assignment in EarthRanger.

A date reads ? → …

The assignment has no start date. Set one in EarthRanger.

The diagram is wider than the widget

Scroll it sideways inside the widget, or open the HTML file saved in the results folder in a browser.

Developing

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-subject-tracking-master-plot-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

Changing a diagram colour or width in spec.yaml has no effect

The styles are fixed in spec.yaml, not on the run form, so recompile after editing them. Colour fields only accept CSS colours (hex, names, rgb()/hsl()); an invalid value fails validation when the workflow runs.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
