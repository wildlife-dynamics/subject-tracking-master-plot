Subject group drop-down

In get_subjects, subject_group_name is typed as "a group name or no filter", which the form shows as an anyOf of a string and null. The spec's rjsf-overrides replace that whole field with a plain, optional string field carrying an EarthRangerEnumResolver transform (type: subject_group_name, depends_on: properties.er_connection.properties.data_source.properties.name). The form then lists the chosen site's subject group names. The override replaces the field rather than annotating the string branch because rjsf-overrides keys are dotted dictionary paths and can't index into the anyOf list. Leaving the field empty sends nothing, so the task's default (None, no filter) applies.

Skip conditions

Every step uses the spec's task-instance-defaults: it is skipped when any input is an empty DataFrame (any_is_empty_df) or any step it depends on was skipped (any_dependency_skipped). So if the site has no assignments or no sources, the diagram step and everything after it are skipped and the dashboard has no diagram. No subjects at all fails the run instead, because get_subjects has raise_on_empty: true.

How the diagram is built

draw_subject_source_diagram (in ecoscope_workflows_ext_mep/tasks/results/_subject_source.py) returns one self-contained HTML document: the pills and lines as inline SVG, the text as HTML labels positioned over it, and a small script for hover highlighting, the details card and copying. No external assets are loaded.

  1. Graph. Assignments are kept only when their subject is in the fetched subjects, so a subject group filter also filters the lines. A source is linked when one of those assignments points at it. With include_unlinked_sources: true every other source on the site is drawn too. An assignment whose source isn't in the sources list still gets a pill, labelled with the first 8 characters of its ID and flagged as missing.
  2. Dates. Each assignment's assigned_range lower and upper bounds are read. An upper bound in year 9999 means open-ended (current); a lower bound in year 0001 means no start (?). A bound that can't be parsed is shown as ⚠ plus its first 10 characters and turns the line red. An assignment is current when it has no end date and no unreadable end date.
  3. Layout. Linked subjects are sorted by name; each spans one row per assignment, with its assignments sorted by date label. Each linked source is placed at the mean row of its assignments and pushed down when it would overlap the one above, which keeps line crossings low. Unlinked subjects and sources follow under Subjects with no source / Sources with no subject, below a rule.
  4. Labels. Subjects show name; sources show manufacturer_id, falling back to collar_id, then id. Labels longer than max_label_chars are cut with …; the full label is kept in a data-full attribute. Hover text adds subject type and subtype, or a source's provider, source type and model. Date labels use the link style's label colours (current, ended, bad date).
  5. Selectable text. All text is HTML (<span class="lbl">) rather than SVG <text>, because browsers select SVG text unreliably. Labels are written column by column (headings, subjects, dates, sources), so a drag down a column selects only that column. A copy handler replaces the clipboard text with each selected label's full value, one per line.
  6. Details card. node_details() builds each pill's text: full label, EarthRanger ID (from the node ID), the hover-text fields, and each assignment as the other end's label plus its date range. These are embedded as JSON in a <script type="application/json"> block, with <, > and & escaped so a label can't end the script. Clicking a pill opens the card beside it; a mouse-up that ends a drag-selection (moved more than 4px) doesn't. Copy uses the Clipboard API and, if that's blocked, falls back to selecting the card's text and document.execCommand("copy"). The fallback is needed because dashboards embed the page in a sandboxed frame.

Styles set in the spec

All three style blocks are given in full in spec.yaml. They match the task defaults except layout_style.font_size, which is 10 here (default 12). The legend above the diagram is built from these values, so it always matches.

Colour fields accept CSS colours only (hex, names, rgb()/hsl()); font and dash fields are restricted in the same way, so a value can't break out of the generated HTML.

Recompiling

spec.yaml is the source; ecoscope-workflows-subject-tracking-master-plot-workflow/ is generated from it by wt-compiler.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh subject_tracking_master_plot --all

The only case is currently studio-run, which sets only the workflow name. The run form also requires er_connection.data_source.name, so add it to the case to test against a site.
